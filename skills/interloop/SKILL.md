# Interloop

Two modes based on args:
- Args contain "init" → **Init Mode** (instrument this project)
- No args (or unrecognized args) → **Session Mode** (run in a second terminal while your coding agent works)

Prerequisites for Init Mode: Claude Code (for `.claude/settings.local.json` hooks), `git`, and `jq`. Session Mode works in any agent runtime once `.interloop/` exists.

---

## Init Mode

### Step 1 — Idempotency Check

Check if `.interloop/` already exists in the current directory.

If it exists:
- Show last-modified dates of each file inside it
- Check `.claude/settings.local.json` for existing interloop hooks (look for `Bash(git commit*)` pattern)
- Report: "Already initialized on [date]. Reinitialize (overwrites stubs, re-merges hooks) or exit?"
- If user says exit, stop here

### Step 2 — Create `.interloop/` Stub Files

Create `.interloop/` directory if needed. Create these four files:

**`.interloop/breadcrumbs.md`**
```
# Breadcrumbs

Generated by coding agent hooks after each git commit. Do not edit manually.
```

**`.interloop/decisions.md`**
```
# Decisions

Decisions captured during interloop sessions. Committed to repo.
```

**`.interloop/open-questions.md`**
```
# Open Questions

Questions awaiting answers. Committed to repo.
```

**`.interloop/session-summary.md`**
```
# Session Summaries

Generated by Stop hook after each coding session.
```

### Step 3 — Configure Hooks in `.claude/settings.local.json`

First, read `<skill-dir>/templates/breadcrumb-agent-prompt.md` to get the breadcrumb prompt text. You will embed this as the `prompt` value in Hook A below.

Ensure `.claude/` directory exists. Read `.claude/settings.local.json` — if it doesn't exist, start from `{}`.

Merge these three hook entries into the file, preserving all existing hooks. For each event array (PostToolUse, Stop, SessionStart): if the array exists, append; if not, create it. Skip if an entry with the same `if` filter or matching pattern already exists (idempotent).

**Hook A — PostToolUse breadcrumb (async agent, fires on git commit):**

Add to `hooks.PostToolUse` array:
```json
{
  "matcher": "Bash",
  "hooks": [{
    "type": "agent",
    "async": true,
    "if": "Bash(git commit*)",
    "model": "sonnet",
    "statusMessage": "Capturing breadcrumb...",
    "prompt": "<INSERT full contents of breadcrumb-agent-prompt.md here — no truncation>"
  }]
}
```

**Hook B — Stop session summary (async command):**

Add to `hooks.Stop` array:
```json
{
  "hooks": [{
    "type": "command",
    "async": true,
    "command": "bash -c '[ -d .interloop ] && { printf \"## Session %s\\n\" \"$(date +\"%Y-%m-%d %H:%M\")\"; git log --oneline -10 2>/dev/null; printf \"---\\n\\n\"; } >> .interloop/session-summary.md' 2>/dev/null || true"
  }]
}
```

**Hook C — SessionStart decisions injection:**

Add to `hooks.SessionStart` array:
```json
{
  "hooks": [{
    "type": "command",
    "command": "[ -f .interloop/decisions.md ] && jq -Rs '{hookSpecificOutput:{hookEventName:\"SessionStart\",additionalContext:(\"## Prior Decisions (from .interloop/decisions.md)\\n\" + .)}}' .interloop/decisions.md || echo '{}'"
  }]
}
```

Note: `jq` safely handles all quoting/escaping. The `|| echo '{}'` fallback means the hook is a no-op when `.interloop/decisions.md` doesn't exist yet.

Write the merged JSON back to `.claude/settings.local.json`. Validate JSON syntax before writing.

### Step 4 — Append CLAUDE.md Snippet

Read `<skill-dir>/templates/CLAUDE_snippet.md`.

Check for `CLAUDE.md` in the current directory:
- If it exists: grep for `## Interloop` marker. If not found, append the snippet to the end.
- If it doesn't exist: create `CLAUDE.md` with just the snippet.

Never append the snippet twice (the `## Interloop` marker is the idempotency check).

### Step 5 — Update `.gitignore`

Check for `.gitignore`. Create it if missing.

Append the following if `.interloop/breadcrumbs.md` is not already in `.gitignore`:
```
# interloop — ephemeral session artifacts (decisions.md and open-questions.md are committed)
.interloop/breadcrumbs.md
.interloop/session-summary.md
```

Do NOT add `decisions.md` or `open-questions.md` — those are committed project artifacts.

### Step 6 — Print Confirmation

```
  ┌─────────────────────────────────────────────┐
  │  INTERLOOP INITIALIZED                       │
  │  Project: <basename of cwd>                  │
  └─────────────────────────────────────────────┘

  .interloop/         created (4 files)
  CLAUDE.md           snippet appended
  .gitignore          2 entries added
  settings.local.json 3 hooks configured
    ✓ Commit breadcrumbs (async, Sonnet)
    ✓ Session summary on Stop
    ✓ Decisions injected on SessionStart

  In terminal 2, start your interloop session:
    /interloop

  The coding agent in this terminal now writes
  breadcrumbs automatically after each commit.
```

If any step was skipped due to idempotency, note it: e.g., "CLAUDE.md snippet already present — skipped".

## Session Mode

Run when invoked as `/interloop` with no args.

### Step 0 — Initialization Check

If `.interloop/` doesn't exist in the current directory:
```
This project hasn't been initialized.
Run /interloop init first, then restart your coding agent.
```
Stop here.

Record the session start time internally (used for git polling).

### Step 1 — Load Context (Parallel)

Run all of these in a single parallel batch:

1. Read `.interloop/breadcrumbs.md`
2. Read `.interloop/decisions.md`
3. Read `.interloop/open-questions.md`
4. Read `.interloop/session-summary.md`
5. `git log --oneline -20` — recent history
6. `git log --since="2 hours ago" --oneline` — active session commits
7. Glob for spec/plan files: `SPEC.md`, `docs/specs/*.md`, `specs/*.md`, `plans/*.md` — read whichever exist
8. `grep -rn "TODO\|FIXME\|HACK\|XXX" --include="*.ts" --include="*.py" --include="*.js" --include="*.go" --include="*.swift" --include="*.rs" . 2>/dev/null | grep -v node_modules | grep -v ".interloop" | head -30`

### Step 2 — Build Question Queue

Build an internal prioritized queue. Do not show the queue to the user — surface one question at a time.

Priority order (highest first):
1. **Breadcrumb uncertainties** — scan `breadcrumbs.md` for entries where `Uncertain:` is not "n/a". Each one becomes a question: "The agent flagged uncertainty about [X] at [time]. What should the behavior be?"
2. **Open questions** — items already in `open-questions.md` not yet answered
3. **Plan gaps** — spec/plan sections where no recent commits touch the relevant area (infer from file paths in breadcrumbs vs. spec sections)
4. **TODO/FIXME comments** — each becomes: "There's a [TODO/FIXME] in [file:line]: '[text]'. Address now or defer?"
5. **Design gap checks** — if queue is otherwise empty, draw from this checklist:
   - What happens when [primary operation] fails mid-way?
   - Is there a rollback or recovery path?
   - Are error messages user-facing or internal-only?
   - What's the auth/permission boundary here?
   - Is there a rate limit or load concern?
   - What does the unhappy path look like for the user?
   - Is there anything that needs documentation before this ships?

### Step 3 — Show Agent Status Dashboard

Print this at session start (and update when new commits arrive):

```
  ┌────────────────────────────────────────────────┐
  │  INTERLOOP                  <HH:MM>             │
  │  Project: <basename of cwd>                     │
  └────────────────────────────────────────────────┘

  Agent activity (last 2 hours)
  ─────────────────────────────────────────────────
  <short-hash>  <time>  <commit subject>
  <short-hash>  <time>  <commit subject>
  (none yet — agent hasn't committed)

  Breadcrumb uncertainties: N
  Open questions:           N
  Decisions logged:         N
```

If no activity yet: "No commits yet — agent is warming up or working on something big."

### Step 4 — Session Loop

Repeat until user says "done", "exit", "stop", or "/interloop stop".

**4a — Check for new commits**

At the start of EVERY turn, run:
```bash
git log --since="<last-check-timestamp>" --oneline 2>/dev/null
```
Update the last-check timestamp. If new commits appeared:
- Surface them briefly: "Agent just committed: [subject]"
- Check new breadcrumbs for new uncertainties — add to queue if found

**4b — Pick next question**

Take the highest-priority item from the queue. Frame it as a focused, specific question with context:

- For breadcrumb uncertainties: "At [time], the agent committed [subject] and flagged this uncertainty: '[text]'. [1 sentence of relevant context from breadcrumbs]. What should the behavior be?"
- For plan gaps: "Your spec mentions [section] but no commits have touched that area yet. Is this in scope for this session, or deferred?"
- For TODOs: "[file:line] has a TODO: '[text]'. Should we resolve this now, defer it, or is it already handled?"
- For design gaps: ask the specific question from the checklist, grounded in what the agent is actually building

Keep questions short. One sentence of context, one sentence question. Never ask compound questions.

**4c — Do work with the answer**

After the user responds:

1. **Always:** Append to `.interloop/decisions.md`:
```
## <HH:MM> — <topic (3-6 words)>
**Question:** <what was asked>
**Decision:** <user's answer, paraphrased concisely>
**Impact:** <what this affects, or "n/a">
```

2. **If the answer resolves an open question:** Remove it from `.interloop/open-questions.md`.

3. **If the answer surfaces new questions:** Add them to queue AND append to `.interloop/open-questions.md`:
```
## <HH:MM> — <topic>
<The question that needs answering>
```

4. **If the answer warrants a doc artifact** (test outline, error spec, API contract, edge case list): offer to draft it. "Want me to draft [X] based on that decision?" If yes, draft it and offer to write it to an appropriate file — but ask before writing to any file outside `.interloop/`.

5. **Brief acknowledgment:** One line confirming what was logged, then flow into the next question naturally.

**4d — Exit cleanly**

When user says done/exit/stop:
```
  Session complete.

  Decisions logged:  N (decisions.md updated)
  Questions added:   N (open-questions.md updated)
  Agent commits:     N commits during this session

  The coding agent will pick up your decisions on next session start
  via the SessionStart hook.
```

### Scope Boundaries

This mode reads widely but writes narrowly:
- **Writes to:** `.interloop/decisions.md`, `.interloop/open-questions.md`
- **Drafts and offers to write:** doc artifacts (with confirmation before writing)
- **Never:** modifies source code, runs tests, makes git commits, touches files outside `.interloop/` without explicit user confirmation
